## August 18, 2026

### Server-side Signal verification

Signal activation now uses an authoritative server-side verification event instead of waiting for browser pixel traffic.

- Call `POST /api/v1/verification-events` with a Signal tracker secret, or use the MCP tool `verify_signal_ingestion`.
- The operation is identity-free and idempotent.
- Verification does not contact Meta, enter attribution or enforcement, or create spend.
- The browser pixel is now optional for activation.

### Consent-aware event ingestion

The Conversion API now requires an explicit legal basis on every `POST /events` request.

- `consent_basis` must be `consent` or `legitimate_interest`.
- Events using `consent` require granted downstream advertising state.
- Browser measurement events require granted consent.
- Legitimate-interest processing is restricted to allowlisted lifecycle events and remains severed from advertising attribution.
- Meta delivery fails closed unless the stored event is consented, observed, joined, and attributed.

This is a breaking request-contract change. Existing server integrations must add the required consent fields before sending new events.

### Signed API contract 0.3.1

The signed OpenAPI contract now publishes version `0.3.1` with ten operations, including `verifySignalIngestion`.

The published `@plainrouter/sdk` and `@plainrouter/cli` packages remain at `0.2.0` and target the previous nine-operation contract. Use direct REST for ingestion verification and for typed event creation until updated packages are released. The CLI can pass the new consent fields through raw `events create --data` JSON, but it does not yet have a verification command.

### More durable creative execution

Governed creative execution now validates staged media before a provider upload, records durable media lifecycle state, and shares a Meta request budget across workers. Temporary provider processing and rate-budget exhaustion can be retried without bypassing policy, approval, or receipt checks.

The MCP creative surface is unchanged: new uploads remain JPEG or PNG proposals, and duplicated ads remain permanently paused at creation.
