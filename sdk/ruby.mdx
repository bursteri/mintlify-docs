[`plainrouter-sdk`](https://rubygems.org/gems/plainrouter-sdk) is the official Ruby SDK for Plainrouter's signed OpenAPI contract. Gem `0.6.1` targets signed API contract `0.5.0` and exposes a compact client over the generated API.

The source is in [`plainrouter/sdk`](https://github.com/plainrouter/sdk/tree/main/packages/ruby). Review release notes before upgrading while the gem remains in the `0.x` series.

## What changes when upgrading?

Version `0.6.1` loads `Pathname` for standalone multipart requests and corrects the Launcher import route. Inventory `GetAccountInventory404Response` is now an anyOf module using `.build`, not a message model with `.new` or `.build_from_hash`. Inspect the selected `ApiRouteNotFound` or account-error branch.

When upgrading from releases before `0.6.0`, replace `PlainRouter::OpenAPI::DeploymentPlan` with `PlainRouter::OpenAPI::DeploymentPlanRead`. Hand-built destination models require `attention_reason`, `held_count` and `notices`. Creative projection classes have also changed; update any explicit class checks using the release notes.

The curated client defaults to JSON responses and raises `PlainRouter::OpenAPI::ApiError` on API redirects without following them. Closed request objects reject unknown keys. Omit an optional page argument for the default and follow returned cursors for incomplete results.

Review the [published release notes](https://github.com/plainrouter/sdk/blob/ruby-v0.6.1/packages/ruby/CHANGELOG.md) and the [shared upgrade checks](/sdk/overview#what-should-i-check-before-upgrading).

## Requirements

- Ruby 3.2 or newer.
- A Signals workspace secret for production Conversion API operations.
- Server-side code. Do not put the secret in browser or distributed client code.

## Install

Install [`plainrouter-sdk 0.6.1`](https://rubygems.org/gems/plainrouter-sdk):

```bash
gem install plainrouter-sdk -v 0.6.1
```

Or add the gem to your `Gemfile`, then run `bundle install`:

```ruby
gem "plainrouter-sdk", "~> 0.6.1"
```

## Create an authenticated client

Pass the Signals workspace secret when you create the client:

```ruby
require "plainrouter"

client = PlainRouter::Client.new(
  token: ENV.fetch("PLAINROUTER_TOKEN")
)

events = client.operations.list_events(per_page: 25)
```

The client sends the Signals workspace secret as a bearer token. It does not read credentials from the environment automatically.

## Send a Meta conversion

This recipe calls Plainrouter's Conversion API, not Meta Graph API directly. Before sending a real purchase, [connect a Meta destination](/signals/connect-meta) and read the actual payment and advertising-consent records from your application. Keep Ruby as the purchase owner; do not also send this purchase through the managed browser or Stripe settlement flow.

The function takes your persisted order ID, original payment time, decimal amount, currency, and consent snapshot. `paid_at` and `consent_captured_at` are Ruby `Time` objects. The consent hash uses symbol keys matching the three API consent fields. Replace the source URL with your checkout URL.

```ruby
require "time"

def send_purchase(client, order_id:, paid_at:, value:, currency:,
                  consent:, consent_captured_at:)
  grants = %i[ad_storage ad_user_data ad_personalization]
  unless grants.all? { |field| consent[field] == "granted" }
    raise ArgumentError, "Recorded advertising consent is required"
  end
  raise ArgumentError, "A stable order ID is required" if order_id.to_s.empty?

  body = {
    event_id: "purchase:#{order_id}",
    event_name: "Purchase",
    event_time: paid_at.to_i,
    event_source: "https://shop.example/checkout/success",
    action_source: "website",
    consent_basis: "consent",
    consent: {
      ad_storage: consent.fetch(:ad_storage),
      ad_user_data: consent.fetch(:ad_user_data),
      ad_personalization: consent.fetch(:ad_personalization),
      captured_at: consent_captured_at.iso8601,
      source: "checkout_cmp"
    },
    value_data: { value: value, currency: currency, order_id: order_id }
  }

  receipt, status, _headers = client.events.create_event_with_http_info(body)
  { event_id: receipt.event_id, duplicate: receipt.duplicate, status: status }
rescue PlainRouter::OpenAPI::ApiError => error
  # Keep credentials and customer payloads out of logs.
  raise "Plainrouter rejected the request (HTTP #{error.code})"
end
```

A new event returns `status: 202`; a retry of the same event ID returns `status: 200` and `duplicate: true`. Persist the payload before sending, and reuse its ID and original payment time after an uncertain timeout. Check that advertising use remains permitted before a later retry. Duplicate ingestion does not resend a failed Meta delivery or update the original event.

### How do I confirm delivery?

Use the returned receipt ID to read the event. This function returns delivery statuses without logging identity fields:

```ruby
def delivery_statuses(client, event_id)
  trace = client.events.get_event(event_id)
  trace.deliveries.map { |delivery| delivery.status }
end
```

`accepted` means Meta accepted a delivery. `queued`, `sent`, or `retrying` means its outcome is pending. An empty list proves no delivery acceptance; inspect the [destination and event eligibility](/signals/connect-meta#troubleshoot). Meta acceptance does not prove ad attribution. See [all delivery statuses](/reference/statuses-and-terms#destination-delivery).

### Handle API failures

| Result | Action |
| --- | --- |
| `401` | Stop retries and check the Signals workspace secret and workspace. |
| `404` when reading | Check the event ID, workspace scope, and retention. |
| `422` | Correct the field errors in `ApiError#response_body`; check consent, timestamps, and decimal-string values. |
| Network timeout | The request may have been accepted. Retry the persisted payload with the same event ID. |

Inspect validation details in a controlled development environment. Do not log the complete exception or response body in production; it can include request-related details. Generated Ruby models do not replace server-side validation.

## Choose an API group

| Group | Use it for |
| --- | --- |
| `client.events` | Create or retrieve an event and verify Signal ingestion. |
| `client.operations` | List events, control destination testing, replay deliveries, read reports, or delete user data. |

Generated models, API errors, configuration, response metadata, and every generated operation remain available under `PlainRouter::OpenAPI`.

## Verify Signal ingestion

```ruby
result = client.events.verify_signal_ingestion
```

The operation is idempotent. A repeated verification returns the existing event with `duplicate: true`. The event confirms ledger receipt but is not real arrival evidence and does not complete onboarding.

## What happened to sandbox methods?

The unauthenticated sandbox is retired. An installed `client.sandbox` facade does not establish availability; its calls return HTTP `410` with `sandbox_retired`. Use the matching workspace credential for supported operations. [Migration guidance](/api/sandbox).

## Configure another API origin or timeout

The default API base URL is `https://plainrouter.com/api/v1` and the default timeout is 30 seconds. Override either value only for a Plainrouter-provided region or a controlled test environment:

```ruby
client = PlainRouter::Client.new(
  token: ENV.fetch("PLAINROUTER_TOKEN"),
  base_url: "https://example.test/api/v1",
  timeout: 20
)
```

## Handle credentials safely

The Ruby SDK accepts a Signals workspace secret for production Conversion API calls. It does not accept an MCP workspace execution token or OAuth management credential.

Keep the secret in server-side credential storage. Never include it in prompts, URLs, logs, source control, or client-side code.

For request and response fields, use the [Conversion API reference](/api/conversions).
