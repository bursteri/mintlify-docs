Use **Campaigns** to inspect retained Meta campaigns, ad sets, ads and daily metrics, then use **Pause**, **Resume**, or an available daily-budget control for a governed change to an eligible object. The MCP inventory tools provide the same kind of stored inspection without making changes. Inventory reads do not contact Meta or trigger a refresh; check freshness before treating them as current account state.

## Before you begin

For the dashboard, sign in to the intended workspace and select an available Meta ad account. For MCP, connect a [Read or Write workspace key](/mcp/workspace-tokens) with an active grant covering the inventory tools. The issuer must still have the required workspace role.

Both tools require `account_id`: the internal Plainrouter account ID, not Meta's external `act_…` identifier. The account must be available to the authorized workspace. An older account-bound key can name only its bound account. Retained data may remain readable for a disconnected account; that does not authorize live provider operations or revive revoked credentials.

## Browse Campaigns

1. Open **Campaigns** and select the intended account.
2. Check the connection indicator, structure-sync time, metrics-sync time and any last-read issue.
3. Expand a campaign to inspect its ad sets and ads. Use **Load more campaigns** and the child load-more control when available; the first visible page is not the complete inventory.
4. Inspect object status and any undo warning before deciding what needs attention.

The page shows retained recent metrics. Missing rows or displayed zero totals do not prove zero provider activity when synchronization is incomplete.

## Pause or resume a campaign, ad set, or ad

You need a signed-in browser session, workspace membership, and an eligible active Meta account and connection. Check [Meta access](/signals/connect-meta#how-do-i-interpret-the-meta-grant) and [workspace policy](/actions/policies-and-safety) first. Retained access to a disconnected account does not authorize changes.

1. Select the intended account in **Campaigns** and expand the hierarchy to the exact object.
2. Choose **Pause** on an active object or **Resume** on a paused object when the control is available. Resume opens a review dialog: check the retained budget and mirror-sync time, then choose **Confirm Resume**. Missing budget data remains unavailable rather than being shown as zero.
3. Read the result and follow **View in Inbox**. The click submits a governed proposal. If you have human approval permission, it also attempts approval; a separate Inbox approval is not always required in Ask. Otherwise, a policy-allowed Ask proposal waits for an authorized reviewer. Full runs admitted changes automatically without a per-change approval.
4. Follow progress and **View receipt** when available. A submission or approval message does not prove that Meta changed the object.

The control uses the selected inventory object as the target. It does not bypass policy, provider-state checks, execution authorization, or verification. Use an available daily-budget control or the [proposal workflow](/api/actions#submit-a-governed-proposal) for budget changes.

### How do I change a daily budget?

1. Open **Edit budget** on an eligible campaign or ad set that owns a daily budget. Ads and objects using a lifetime or parent-owned budget do not expose this control. The account currency and retained daily budget must be available.
2. Enter a different positive amount in the displayed account currency, using your locale's decimal separator. Plainrouter converts it using Meta's currency offset; do not multiply every currency by 100.
3. Review **Current mirror budget**, **New budget**, the absolute and percentage change, and **Mirror sync**. These are retained values; execution rechecks Meta.
4. Choose **Confirm budget change**, then follow the batch and receipt in Inbox.

Unknown currency precision, malformed amounts and unchanged budgets cannot be submitted. Spending and revenue displays are different quantities: Meta budget minor units must not be reused for Signals decimal-string revenue. See [Actions inputs](/api/actions#submit-a-governed-proposal).

### How do I verify a Pause or Resume?

| Display | Meaning and next step |
| --- | --- |
| **Awaiting approval** or **Queued** | A proposal exists, but a verified provider change is not established. Follow it in Inbox. |
| **Executing** or **Undoing** | Work is in progress. Do not submit another change to bypass it. |
| **Done** | The related execution receipt records a verified result and verification time. Inspect the receipt for the exact outcome. |
| **Inventory awaiting refresh** | The action is verified, but retained inventory has not yet caught up with the expected status. The control stays unavailable until retained inventory shows the expected status or budget, or a sync completed after verification replaces the older observation. A newer conflicting observation settles the old refresh wait; check the displayed current value before another change. |
| **Blocked**, **Failed**, or **Undone** | Inspect the reason and receipt. These states do not mean the original requested change succeeded. |

Plainrouter does not optimistically rewrite retained inventory when you click a control. Another unsettled management proposal can also keep the same target unavailable. Follow that batch to its outcome; review or reject it only when a pending decision is still allowed. See [proposal conflicts](/api/actions#why-is-a-management-target-refused) and [recovery evidence](/actions/audit-log).

## Read objects with MCP

Call `get_account_inventory` with tool arguments such as:

```json
{
  "account_id": 91,
  "level": "campaign",
  "limit": 100
}
```

The response contains `account`, `sync`, `staleness`, `objects` and `next_cursor`. Verify the returned account first.

| Input | Meaning |
| --- | --- |
| `account_id` | Required positive internal account ID. |
| `level` | Optional `campaign`, `adset`, or `ad`. Inventory uses `adset`; action proposals use `ad_set`. |
| `effective_status` | Optional Meta status, such as `ACTIVE`, `PAUSED`, or `ARCHIVED`. |
| `campaign_id`, `adset_id` | Optional external Meta parent IDs. |
| `after_id` | Positive internal object-row cursor from the previous `next_cursor`. |
| `limit` | 1–200 objects; default 100. |

When `next_cursor` is non-null, repeat the same request with that value as `after_id`. Stop when it is null. Keep filters unchanged between pages. An object's internal `id` is not its external Meta `external_id`.

Objects include configured/effective status, hierarchy, available budget fields, sync timestamps and related Plainrouter receipt fields. Budget fields ending in `_minor` use integer currency minor units; unavailable values remain null.

## Read retained metrics and changes

Call `get_inventory_metrics`:

```json
{
  "account_id": 91,
  "start_date": "2026-09-20",
  "end_date": "2026-09-26",
  "include_changes": true
}
```

Use dates appropriate to your account's available history. Optional `campaign_id`, `adset_id` and `ad_id` filters use external Meta IDs. Dates use `YYYY-MM-DD`; the end cannot precede the start.

The response contains `metrics`, `object_metrics`, `unmatched_arrivals`, `changes`, `effective_range`, account details and freshness. Daily `metrics` rows include currency, spend, impressions, clicks, inline link clicks, Meta action data, fetch time and counted arrivals. Spend is a decimal string in the account currency; do not interpret it as an integer minor-unit budget field.

Date bounds are inclusive in the account timezone, with UTC as the fallback. Plainrouter clips the requested range to the workspace's customer-visible retention cutoff and today. Inspect `effective_range` rather than assuming the full request was returned. If no range remains, it is null and `metrics`, `object_metrics` and `changes` are empty. `changes` is populated only when `include_changes` is true; it records observed field changes, not a complete causal audit of every Meta edit.

### Read the same metrics over REST

Use a Read or Write Workspace key with an active `get_inventory_metrics` grant for the workspace and account. A Signals Server secret cannot authenticate this route. Replace workspace `42`, internal account `91` and the dates with your own values; load the key from server-side secret storage.

```bash
curl --fail-with-body --get \
  https://plainrouter.com/api/v1/workspaces/42/admin/ad-accounts/91/inventory/metrics \
  --header "Authorization: Bearer $PLAINROUTER_WORKSPACE_KEY" \
  --header 'Accept: application/json' \
  --data-urlencode 'start_date=2026-09-20' \
  --data-urlencode 'end_date=2026-09-26' \
  --data-urlencode 'include_changes=1'
```

The response has the same top-level comparison fields described below. This read does not call Meta or refresh inventory. Account scope, date filters and nullable values still apply. The [public OpenAPI contract](https://plainrouter.com/openapi.json) defines the route and authentication.

### How do counted arrivals compare with Meta metrics?

Use API or MCP `object_metrics` to compare a retained campaign, ad set or ad on the same account-local date. The **Campaigns** dashboard currently shows retained Meta metrics; the counted-arrival comparison is available through these read interfaces.

| Field | Interpretation |
| --- | --- |
| `level`, `external_id`, `date` | The mirrored object and account-local day. Levels are `campaign`, `adset`, and `ad`. |
| `meta` | Stored Meta spend, impressions, clicks and inline link clicks for that object/day; `null` when no matching Meta metrics are retained. |
| `arrivals` | Eligible observed Meta arrivals whose numeric object IDs match retained inventory. `0` is an available count with no matches for that row; `null` means arrival counting is unavailable. |
| `unmatched_arrivals` | One workspace/window count of eligible arrivals that matched no readable inventory object. It is not an account total or a count restricted by your object filters. Unknown IDs are not exposed. |

An arrival can match its campaign, ad set and ad. Do not sum all hierarchy levels into a total: that would count the same arrival more than once. Rows can contain arrivals without Meta metrics, or Meta metrics without matching arrivals.

To verify a comparison, confirm `account` and `effective_range`, choose one hierarchy level, then inspect dates, object IDs, freshness and nullable fields. Check your [snippet installation and captured URL fields](/signals/install-pixel#which-arrival-fields-are-retained), numeric Meta object IDs in the ad's URL tags, and inventory synchronization when matching counts are missing. An unavailable arrivals store is not a measured zero.

These arrivals count eligible observations, not unique people, purchases or Meta-attributed conversions. Meta clicks and arrivals can differ. This comparison is separate from [Signals reconciliation](/signals/health-and-performance) and does not establish causal lift or admissible quantitative proposal evidence by itself.

### Which creative produced an ad?

Ad-level metrics can include `creative_id`, `generator`, `generator_job` and `parent_creative`. Plainrouter resolves these fields from a related creation receipt and a creative in the same workspace. Campaign and ad-set rows do not inherit an ad's provenance.

Treat null fields as unknown. A Meta ad without a related Plainrouter creative receipt can have metrics while all four fields remain null; a creative name or arbitrary URL tag is not proof of its generator. These fields describe recorded provenance, not comparative creative quality or performance. See the [creative workflow](/actions/creative-workflow) for the separate asset-selection and approval process.

## What do freshness and undo warnings mean?

| Field or state | Interpretation and next step |
| --- | --- |
| `fresh` | Stored timestamps meet the applicable freshness threshold; this is not a live Meta read. |
| `behind` | Stored structure or applicable metrics are behind. Check timestamps and last error before relying on them. |
| `never_synced` | No structure sync is recorded. An empty response does not prove the account has no campaigns. |
| `reconnect_needed`, `disconnected` | Retained data may be present, but the connection is not ready for current provider work. Review [Meta connection setup](/signals/connect-meta). |
| `created_by_plainrouter` and receipt fields | A related Plainrouter creation receipt is available; inspect its exact status and verification result. |
| `undone_but_active` | A compensated receipt exists, but the stored object's effective status is `ACTIVE`. Investigate the conflicting evidence. |
| `undo_failed` / **Undo failed** | The deciding receipt records compensation failure and the stored object is not `ARCHIVED`. Do not report successful undo. |

Follow [Inbox and current disposition](/actions/review-proposals#current-disposition-and-late-restoration) and [Audit](/actions/audit-log) before retrying uncertain or failed recovery. Reading this inventory never performs an undo.

## Troubleshoot access and incomplete results

- **Account not found or outside key binding:** check the internal account ID, workspace access and older key binding. Trying another workspace's ID cannot widen access.
- **Missing tool or insufficient scope:** inspect discovery and the active grant; replace a credential with the intended permitted scope if necessary. Read-only inventory does not require the separate Write-only Actions record-read grant.
- **Only some objects appear:** follow `next_cursor`; remove unintended status/parent filters and check freshness.
- **Dates return less history:** inspect `effective_range` and the workspace retention limit. Empty retained results are not proof of zero provider activity.
- **Arrival counts are missing or do not match clicks:** distinguish `null` from `0`, inspect matching tags and freshness, and compare one hierarchy level over the same dates. Do not add the workspace's unmatched count to a filtered ad total.

Tool names and input contracts are published in the [Plainrouter MCP server card](https://plainrouter.com/.well-known/mcp/server-card.json); response fields are defined in the [public OpenAPI contract](https://plainrouter.com/openapi.json). For live image/video asset selection, use the separate [creative-library workflow](/actions/creative-workflow).
