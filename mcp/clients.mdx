## Endpoints and access

| Connection | Endpoint | Authentication |
| --- | --- | --- |
| Sandbox | `https://plainrouter.com/mcp/sandbox` | None. Synthetic data, no Plainrouter account, never contacts Meta. |
| Production | `https://plainrouter.com/mcp` | Streamable HTTP with `Authorization: Bearer …` using a Workspace key, or client-supported Plainrouter OAuth sign-in. |

[Create a Workspace key](/mcp/workspace-tokens) for the intended workspace or fixed set of workspaces. For multiple workspaces, use `list_workspaces` and pass `workspace_id` on subsequent tool calls. Read covers analysis; Actions require Write, including their record-read tools. Keep credentials in protected client settings, never prompts or source control. OAuth clients obtain workspace-scoped execution credentials through sign-in instead of requiring a pasted key.

**Ask** waits for approval; **Full** runs policy-allowed changes automatically. Rule violations are blocked either way. Client permission prompts do not override [Plainrouter policy](/actions/policies-and-safety).

## What proves the connection worked?

Inspect a real tool result. In the sandbox, a successful read contains `sandbox: true`. In production, a read must return the intended workspace. A discovered tool list or an assistant saying “connected” does not prove authenticated access. Agent wording can vary, and connecting a client does not verify conversion delivery or ad execution.

For another client, use the [transport and authentication reference](/mcp/setup#which-mcp-protocol-should-my-client-use). For conversion sending without an agent, start with [n8n and Make automation](https://plainrouter.com/solutions/automation).
