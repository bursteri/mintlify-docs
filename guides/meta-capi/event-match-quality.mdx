title: "Meta Event Match Quality"
description: "Read PlainRouter's stored Meta Event Match Quality history, interpret score changes, and improve consented matching inputs safely."

Meta Event Match Quality (EMQ) measures how much valid customer and browser context Meta can use to match server events. PlainRouter stores Meta's dataset-quality snapshots and exposes the recent history through the dashboard and `GET /reports/emq`.

EMQ is not a delivery-success rate, attribution-lift estimate, or conversion count. Read it alongside delivery acceptance and reconciliation rather than treating it as a standalone performance result.

## How PlainRouter calculates the displayed score

PlainRouter's scheduled measurement reads Meta's Dataset Quality response, extracts the available web-event `composite_score` values, and stores their average rounded to two decimals.

The Signals dashboard displays the latest stored score on a 0–10 scale. Opening the dashboard or calling `GET /reports/emq` reads stored snapshots; it does not make a new live Meta request.

Each snapshot contains:

| Field | Meaning |
| --- | --- |
| `score` | Stored average of Meta's available web composite scores. |
| `week_over_week_change` | Relative percentage change from an eligible snapshot at least seven days older. |
| `alerted` | Whether the relative decline crossed PlainRouter's configured drop threshold. |
| `measured_at` | Time PlainRouter captured the snapshot. |
| `platform_response` | Stored provider response used to derive the score. |

`week_over_week_change` is a percentage change, not a score-point difference. A change from `8.0` to `7.2` is `-10%`, not `-0.8%`.

## Read EMQ with the TypeScript SDK

Use the same Signals workspace secret as other Conversion API operations:

```ts
import {
  configurePlainrouter,
  getEmqReport,
} from "@plainrouter/sdk";

const signalSecret = process.env.PLAINROUTER_SIGNAL_SECRET;
if (!signalSecret) throw new Error("PLAINROUTER_SIGNAL_SECRET is required");

configurePlainrouter({ signalTrackerSecret: signalSecret });

const result = await getEmqReport();

if (result.error) {
  throw new Error(`Unable to read EMQ: ${JSON.stringify(result.error)}`);
}

const latest = result.data.snapshots[0];

if (!latest) {
  console.log("No stored EMQ snapshot yet");
} else {
  console.log({
    score: latest.score,
    weekOverWeekPercent: latest.week_over_week_change,
    alerted: latest.alerted,
    measuredAt: latest.measured_at,
  });
}
```

The API returns up to 90 snapshots in descending `measured_at` order. An empty list means no snapshot has been stored for this workspace; it does not mean the score is zero.

## Improve match inputs without inventing data

For an eligible event, send accurate fields that your policy permits and your application actually knows:

- `email` and `phone` from a verified checkout or account record.
- `first_name`, `last_name`, `city`, `zip`, and two-letter `country` when reliable.
- A stable, non-personal `external_id` when your identity policy permits it.
- `client_ip_address` and `client_user_agent` from the originating request when appropriate.
- Valid `fbp` and `fbc` values from a consenting browser.

PlainRouter normalizes and SHA-256 hashes raw identity values to Meta's required format. It preserves already SHA-256-hashed values and forwards valid network and Meta browser identifiers in their required unhashed form.

Do not add fabricated values, copy one visitor's identifier to another event, or loosen consent to chase a higher score. Incorrect match data can make the metric look better while making the underlying measurement less trustworthy.

## Diagnose a score drop

Check the measurement pipeline in this order:

1. Confirm `measured_at` is recent enough for the comparison you are making.
2. Check whether the mix of event types or traffic sources changed.
3. Inspect recent event payloads for missing identity fields, `fbp`, or `fbc`.
4. Confirm your consent integration still grants and transmits the intended fields.
5. Check delivery acceptance for authentication or permanent failures.
6. Confirm another integration did not start sending lower-context events to the same dataset.

A score can change because the event population changed, even when the code did not. Compare like event types and time windows before attributing the change to one deployment.

## Keep EMQ separate from delivery and deduplication

- EMQ describes match context for eligible server events.
- Delivery acceptance describes whether destination deliveries reached an accepted state.
- `event_id` deduplication helps Meta recognize browser and server copies of one event.
- Reconciliation compares stored accepted gateway counts with Meta-reported counts.

Use [Signal health and performance](/signals/health-and-performance) for the combined view and [Meta `event_id` deduplication](/guides/meta-capi/event-id-deduplication) for the browser/server pairing contract.
