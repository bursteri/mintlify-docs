Verify the email address on your Plainrouter account to use protected account access. You can also enable optional two-factor sign-in from **Settings → Profile**. Plainrouter uses an emailed sign-in link/code or Google. Optional two-factor sign-in adds an authenticator challenge to web sign-in; it is separate from workspace roles and API credentials.

## Why is access paused until I verify my email?

An unverified email pauses protected web access, new mobile sign-in, MCP/agent access issued by that person, Management keys and Workspace keys. A pending email change keeps your current address and access active until the new address is confirmed. Unverified current addresses still require verification. A valid key string does not bypass the issuing person's verification or current role.

On **Verify your email**:

1. Open the verification message sent to the displayed address and follow its link while signed in to the intended account.
2. If the address is wrong, choose **Change email**, enter the right address and choose **Save email**.
3. For an expired or mismatched link, choose **Resend verification email** and use the new message for your current address. Resends are limited to six per hour per account; wait if the screen reports too many emails.
4. Return to the intended page or retry the authorized client operation. Verification restores eligibility; it cannot restore an expired or revoked key or grant.

Email verification does not grant access to another workspace or Meta ad account. A Signals **Server secret** remains a separate Conversion API credential; do not replace it with a Workspace key. [Choose the right credential](/api/authentication).

## How do I change my email without losing access?

Open **Settings → Profile**, choose **Edit** beside your email, and enter the new address. Approve the change from the message sent to your current mailbox, then verify the new address using the separate message sent there. Your current email and access remain active while confirmation is pending. If two-factor sign-in is enabled, complete **Confirm it's you** when asked.

A link opens a confirmation page; use its confirmation action to complete the step. Opening a link alone is not confirmation. The profile identifies the pending stage and offers resend or cancel controls. A canceled or superseded link cannot finish a later request. Keep account links private and use the intended signed-in account when the page requests sign-in.

## How do I sign in or confirm a sensitive action?

Use **Continue with Google** or **Continue with email**. The email flow sends a sign-in link and code that work in the requesting browser for ten minutes. Follow the message or choose **Enter code manually**. Request a fresh message when it expires; do not send a sign-in code to an agent or put it in an API bearer header.

Plainrouter no longer asks for an account password. For a sensitive action, **Confirm it's you** uses a fresh emailed code or, when two-factor sign-in is enabled, an authenticator code or recovery code. Follow the displayed method; the email sign-in code and authenticator code are different credentials.

## How do I enable two-factor sign-in?

Before starting, use an authenticator app and a private place to save recovery codes. Never send a setup key, QR code, authentication code or recovery code to an AI assistant, support conversation or public repository.

<Steps>
  <Step title="Open your profile">
    Open **Settings → Profile** and find **Two-factor sign-in**. Choose **Confirm it's you** and complete the displayed verification to unlock two-factor management.
  </Step>
  <Step title="Enable and confirm">
    Choose **Enable two-factor sign-in**. Scan the QR code or enter the setup key in your authenticator app, then enter the app's **Authentication code** and confirm setup.

    Setup is not complete while the screen says **Finish setup by confirming an authentication code**. Confirm that it says **Two-factor sign-in is enabled**.
  </Step>
  <Step title="Keep recovery access">
    Save the recovery codes privately. **Show recovery codes**, **Regenerate recovery codes** and **Hide recovery codes** let you manage the displayed set after identity confirmation.
  </Step>
  <Step title="Check the next web sign-in">
    At the two-factor challenge, enter your authenticator code. If you need a saved recovery code instead, choose **Use a recovery code**. Google web sign-in also requires this challenge once two-factor sign-in is enabled.
  </Step>
</Steps>

Use web sign-in for the setup steps above. Confirming two-factor setup also revokes existing mobile sign-in credentials. Failed challenge attempts are limited across the account, so switching browser sessions does not reset the limit.

## How do I change or disable two-factor sign-in?

Return to **Settings → Profile → Two-factor sign-in** and complete **Confirm it's you** when asked. Choose **Cancel setup** for unfinished setup or **Disable two-factor sign-in** for an enabled setup. If confirmation has expired, unlock management again before retrying. Keep recovery codes private when reviewing or regenerating them.

A browser sign-in and an [MCP Workspace key or OAuth connection](/mcp/setup) are different credentials. Do not put an authenticator code into an API bearer header. Workspace permissions, required Actions approvals and provider verification still apply after sign-in.

## Where can I read the security policy or report a concern?

Read the [public security policy](https://plainrouter.com/security) and its [security contact record](https://plainrouter.com/.well-known/security.txt). Follow that policy for reporting a concern; never include account credentials or recovery material. The workspace's [Actions audit history](/actions/audit-log) records advertising decisions and receipts; it is not a general account-security event export.
