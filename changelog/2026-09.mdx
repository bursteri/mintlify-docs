Plainrouter ships continuously. This page collects the customer-facing changes from September and leaves out formatting, CI, and internal draft work.

<Update label="September 23, 2026">

  ## Read provider connection health through MCP

  **New** · `get_account_state` now includes `connection.health`, using the same workspace-specific provider status as Connections. It distinguishes `not_connected`, `revoked`, `attention_needed`, and `connected` while preserving the existing raw connection status. [Interpret connection health](/mcp/tools#how-should-i-interpret-connection-health).
</Update>

<Update label="September 22, 2026">

  ## Preserve action history when deleting a login

  **Fixed** · Past Actions decisions no longer prevent an otherwise eligible account deletion solely because they reference the user. Plainrouter disables the deleted identity while preserving retained evidence. Accounts that own teams with retained Actions records can still be refused deletion. [Understand retained history](/actions/audit-log#what-happens-to-history-after-account-deletion).

  ## Keep bearer headers off dashboard requests

  **Changed** · Session-only dashboard routes reject requests carrying a bearer credential even when a valid browser session is also present. API and MCP credentials keep their separate interfaces. [Resolve a dashboard authentication error](/api/authentication#why-does-a-dashboard-url-reject-my-bearer-token).


  ## Download action decision receipts

  **New** · Audit rows with a stored receipt offer **Download decision receipt**. The JSON records the action decision, terminal status, available provider evidence, verification result, document digest, and audit-chain reference. A receipt can record failure as well as success. [Inspect a decision receipt](/actions/audit-log#download-an-action-decision-receipt).
</Update>

<Update label="September 21, 2026">

  ## Cancel a pending server-secret rotation

  **New** · **Server secret → Discard** cancels a pending replacement while keeping the current secret valid. Integrations already using the replacement must switch away from it. **Revoke** remains the option that invalidates the current secret too. [Manage a pending replacement](/api/authentication#discard-a-pending-replacement).

  ## Start Signals tasks from MCP prompts

  **New** · Production MCP clients can discover `install_the_count`, `claimed_vs_counted`, and `signal_health`. These argument-free prompts return instructions for the existing Signals tools; they do not execute tools or bypass workspace permissions. [Use a built-in prompt](/mcp/setup#use-a-built-in-signals-prompt).


  ## Arrival counting is free on every plan

  **Changed** · Arrivals are no longer billed or capped, and arrival allowances and overage charges have been removed. Your price follows your observed ad-spend band. Free includes 30 days of history; paid plans include 12 months. [Review pricing and billing](/billing/overview).

  ## Connect ad platforms with the right team permissions

  **Improved** · Team members can finish an initial or incomplete ad-platform connection. Replacing a healthy connection and disconnecting it remain admin/owner actions. Connections now shows each platform's controls according to those permissions; workspace-owner settings for Meta delivery and Stripe remain separate. [Check connection permissions](/signals/connect-meta#who-can-connect-or-change-an-ad-account).
</Update>

<Update label="September 20, 2026">

  ## Read Signals installation and arrivals through MCP

  **New** · `get_install_instructions` returns managed-hostname installation material and stored first-arrival state. `get_arrivals_comparison` returns the workspace's stored arrivals and platform-click comparison for 7, 30, or 90 days. Both are read-only production tools available with authorized Read keys, without ad-account selection. [Use the Signals tools](/mcp/tools#get_install_instructions).


  ## Manage workspace keys through the API

  **New** · Developers can use a Management key to list accessible workspaces and create, list, or revoke their own workspace keys. Current team members can also manage their keys in Settings, with Read or Write issuance limited by their current role. Management keys remain separate from MCP execution credentials; deleting one does not revoke the workspace keys it issued. [Use the management API](/api/authentication#how-do-i-use-the-management-api).
</Update>

<Update label="September 19, 2026">

  ## Separate developer keys, agent keys, and server secrets

  **Changed** · **Settings → Management keys** and **Settings → Workspace keys** replace the previous token surfaces. New workspace keys offer Read or Write access and can select eligible active accounts owned by their workspace; older account-bound keys keep their restriction. The Signals secret now lives under **Workspace settings → Server secret**. [Create a workspace key](/mcp/workspace-tokens) or [choose the right credential](/api/authentication).

  ## Open proposals with an explicit Inbox link

  **Improved** · Action proposal responses now include `inbox_url`. The existing `approval_queue_url` remains an alias, so existing clients can continue to open the same human-review workflow. [Follow a creative proposal](/actions/creative-workflow#4-follow-the-human-decision-and-final-outcome).

  ## Check creative images before preparing an ad

  **New** · The free [Meta Ad Image Checker](https://plainrouter.com/tools/meta-ad-checker) inspects JPEG/PNG dimensions and file size, previews a center crop, and exports custom review margins. Processing stays in the browser. Its checks are design aids, not Meta approval or official safe-zone verification. [Use the creative workflow](/actions/creative-workflow#image-upload-rules).

  ## Resize the desktop app sidebar

  **Improved** · Drag the sidebar edge to resize, collapse, or expand it. Plainrouter remembers the preferred width in the browser.
</Update>

<Update label="September 18, 2026">

  ## Manage API secrets and MCP tokens separately

  **Improved** · **Settings → API secret** manages the Signals secret used by REST, SDKs, and the CLI. **Tokens** manages account-bound MCP credentials, including issuance, rotation, revocation, and a **Show revoked** option. [Manage the API secret](/api/authentication#where-do-i-manage-the-signals-api-secret) or [issue a workspace token](/mcp/workspace-tokens).

  ## Manage provider connections in one place

  **Improved** · **Connections** brings together Meta reporting and dataset setup, Google Ads spend reads, Stripe revenue webhook configuration, and site installation links. Provider configuration and verified event delivery remain separate checks. [Connect Meta](/signals/connect-meta) or [configure Stripe revenue](/signals/track-events#verify-stripe-checkout-settlement).

  ## Review Actions in Inbox and export audit history

  **Improved** · **Inbox** groups actions by decision and verification state. **Audit** adds Actor and Outcome filters plus **Download JSON** for the workspace's audit events. Suggest-only approvals appear in Inbox's **Landed** group as **Approved without execution**; they do not create a provider change. [Review proposals](/actions/review-proposals) or [trace audit events](/actions/audit-log).
</Update>

<Update label="September 17, 2026">

  ## Connect MCP clients with stateless discovery

  **Improved** · Plainrouter MCP server `0.4.0` supports protocol `2026-07-28` with `server/discover` and per-request protocol metadata. Legacy `initialize` clients remain supported. Custom HTTP clients using the modern protocol must send matching MCP headers. The server no longer issues a session ID. Workspace-token and approval requirements remain unchanged. [Check client compatibility](/mcp/setup#which-mcp-protocol-should-my-client-use).
</Update>

<Update label="September 16, 2026">

  ## Install Signals directly from Dashboard and Signals

  **Improved** · Before the first arrival, Dashboard and Signals display installation instructions directly, including the CNAME and snippet for a provisioned managed hostname. Sample dashboard charts have been removed. Same-origin forwarding details open automatically when Path B is selected. [Install Signals and verify collection](/signals/install-pixel).
</Update>

<Update label="September 14, 2026">

  ## Install Signals before connecting Meta

  **Improved** · Saving a website address now opens **Install** directly. Meta authorization and dataset selection remain optional for arrival collection, and **Continue without Meta** provides a way back when assets are unavailable. [Follow the updated quickstart](/quickstart#set-up-signals).

  ## Choose the collection hostname before provisioning

  **Improved** · Managed-hostname setup suggests `t` on your website domain and lets you edit that DNS label on Install before confirming it. The final stored hostname supplies the CNAME and snippet; it cannot be renamed after provisioning. [Choose your hostname](/signals/configure-dns#choose-your-collection-hostname).

  ## Server-event acknowledgements flag invalid consent timestamps

  **New** · New secret-authenticated event acknowledgements include `warnings`. The `consent_captured_at_invalid` warning identifies a missing or invalid capture time when visitor or user identity is supplied. Event acceptance and duplicate responses retain their existing semantics. [Handle the warning](/api/conversions#why-is-the-consent-capture-time-invalid).

  ## Published agent skills use workspace execution tokens

  **Fixed** · The published account-context, ingestion-verification, and governed-proposal skills now distinguish workspace execution tokens from OAuth management credentials and Signals workspace secrets. The proposal skill uses the supported creative workflow and preserves human approval and verification requirements. [Choose the correct MCP credential](/api/authentication#how-do-i-authenticate-plainrouter-mcp) and [follow the creative walkthrough](/actions/creative-workflow).

</Update>

<Update label="September 13, 2026">

  ## Meta comparisons distinguish missing reads from reported data

  **Improved** · Signals and CSV exports show stored Meta clicks, impressions, and account-currency spend with daily **Reported**, **Read but not reported**, and **Not yet read** states. Incomplete reads remain unavailable rather than becoming assumed zeros. [Read the comparison](/signals/health-and-performance#platform-read-state).
</Update>

<Update label="September 12, 2026">

  ## Connect a Meta ad account for reporting

  **Improved** · The Signals overview's Meta connection flow asks you to select a business portfolio and ad account for platform reporting. Conversion-destination setup remains separate. [Choose the connection you need](/signals/connect-meta#connect-meta-for-reporting).
</Update>

<Update label="September 10, 2026">

  ## Recover a removed collection hostname

  **Fixed** · Signals now identifies a managed hostname removed at Cloudflare and offers **Re-provision hostname**. Re-provisioning preserves the removed record as history. [Recover the hostname](/signals/configure-dns#cloudflare-removed-the-collection-hostname).

  ## Workspace grants can be revoked through MCP

  **New** · Execution calls check an active workspace grant for the requested operation. The authorized `revoke_grant` tool stops further operations under that grant and records an audit event. [Review grant revocation](/mcp/tools#revoke_grant).

  ## Legacy Launcher is disabled by default

  **Changed** · Legacy Drive connection, inventory sync, file import, and `launcher.*` MCP tools require explicit feature enablement. [Check Launcher availability](/launcher/connect-drive).

  ## Free conversion checks are available in the browser

  **New** · Inspect synthetic payloads, event IDs, cookies, and field coverage, or build campaign URLs with the [Library's implementation guides and local checks](https://plainrouter.com/library). Local checks do not establish platform delivery or Meta match quality.

  ## Landing click IDs stay in document memory

  **Privacy** · The v4 snippet keeps landing click IDs in the current document's memory and sends them only with fully consented events. It retires the `pr_click_ids` cookie and drops malformed click-ID entries individually without discarding valid entries. Meta's consent-gated `_fbc` and `_fbp` cookies remain separate. [Review click-ID handling](/signals/track-events#how-landing-click-ids-are-handled).

  ## Team names stay aligned with Stripe

  **Fixed** · Renaming a team in settings or during billing checkout now updates its existing Stripe customer after the name is saved. A temporary Stripe failure leaves the saved name intact. [Review billing setup](/billing/overview).
</Update>

<Update label="September 9, 2026">

  ## Arrival totals remain complete when a small cell is withheld

  **Improved** · Signals and CSV exports retain complete arrival totals, including totals below five. A withheld strict-EU subtotal is labeled separately and does not reduce the total or difference calculation. Completed reporting windows and **Today so far** remain separate. [Interpret the totals](/signals/health-and-performance#events-received).
</Update>

<Update label="September 8, 2026">

  ## Find the right Meta Pixel during setup

  **Improved** · Signals setup starts with the website address and offers a searchable dataset/Pixel picker. Saving a destination returns to the overview, where **Install** opens collection-domain setup. [Connect the destination](/signals/connect-meta#connect-the-destination).

  ## Accept and manage team invitations

  **Improved** · Invitations continue through login or registration and require an explicit **Join** action with the invited email. Links last seven days; owners can resend or cancel pending invitations. [Join an invited team](/quickstart#join-an-invited-team).

  ## Retention instruction records are retired

  **Changed** · The former retention-instruction history and export have been removed. Workspace identity-retention policy continues to apply. [Review current retention behavior](/signals/overview#identity-retention).

  ## Arrivals are counted on page load

  **Improved** · The v4 snippet sends one identity-free arrival per document load before consent evaluation, on both managed-hostname and same-origin installations. Consent changes and in-app navigation do not add arrivals. Conversion events, visitor identity, and Meta delivery remain consent-gated. [Verify the arrival request](/signals/install-pixel#verify-the-installation).

  ## Ad-account onboarding is optional

  **Improved** · Continue to Signals setup without connecting an ad account, or skip to the dashboard and return later. Signals setup starts with the website address, keeping it separate from the collection-domain DNS instructions. [Follow the quickstart](/quickstart).

  ## Dashboard charts are clearly marked as a preview

  **Improved** · The dashboard offers customizable charts labeled as sample data. Workspace, team, and profile names save on blur, and appearance settings include System mode. Use Signals for actual website measurements.
</Update>

<Update label="September 7, 2026">

  ## Signals centers the overview on website measurement

  **Improved** · The workspace Signals page now presents collection status, arrivals and platform activity, and verified revenue. Account-scoped gateway delivery, EMQ, and reconciliation diagnostics remain available through MCP. [Read Signals measurements](/signals/health-and-performance).
</Update>

<Update label="September 6, 2026">

  ## Billing checkout includes your company or team name

  **Improved** · The dashboard guides eligible paid workspaces into hosted Stripe Checkout and asks for the company or team name used on invoices. Workspaces joining an existing team subscription show a synchronization notice. [Complete billing setup](/billing/overview#how-do-i-complete-checkout).
</Update>

<Update label="September 5, 2026">

  ## Self-serve Signals setup now waits for real traffic

  **Improved** · Open registration now leads directly into a Signals setup that issues the workspace API secret once, guides DNS and browser installation, and turns green only after Plainrouter stores a real eligible arrival. The identity-free REST and MCP verification event remains available as a write-path diagnostic, but it no longer counts as onboarding evidence. [Follow the self-serve quickstart](/quickstart).

  ## New installations use the v4 collector

  **New** · Every generated managed-hostname, onboarding, and same-origin installation now loads `/s/v4.js`. The live collector is served from Plainrouter's dedicated `cname.plainrouter.app` origin behind each customer collection domain, while previously published major URLs remain available for existing installations. [Install the current Signals pixel](/signals/install-pixel).
</Update>

<Update label="September 4, 2026">

  ## Signals setup removes the retention questionnaire

  **Improved** · New Signals setup uses the 90-day identity-retention default without asking you to fill out a legal-profile or retention questionnaire. Server-side retention policy continues to apply. [Review identity retention](/signals/overview#identity-retention).

  ## Pricing is pinned at the first paying invoice

  **Improved** · Plainrouter pins the pricing table when the first paying invoice is reserved, rather than when an account is created. [Understand the pricing basis](/billing/overview).
</Update>

<Update label="September 3, 2026">

  ## Connect Stripe revenue from workspace settings

  **New** · Workspace settings now provide the callback URL and signing-secret setup for Stripe verified revenue. Paid Checkout Sessions can produce verified purchase events in Signals. [Connect Stripe revenue](/signals/track-events#verify-stripe-checkout-settlement).

  ## EUR pricing includes arrival allowances

  **Improved** · This release introduced observed-spend pricing bands with arrival allowances and overage charges. **Superseded September 21:** arrival counting is now free on every plan, without arrival caps or overage charges. [Review current pricing and billing](/billing/overview).
</Update>
